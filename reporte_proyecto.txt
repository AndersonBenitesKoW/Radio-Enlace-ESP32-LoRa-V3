           REPORTE TECNICO - SISTEMA DE MONITOREO DE RADIOENLACE LoRa
================================================================================

1. DESCRIPCION GENERAL DEL PROYECTO
--------------------------------------------------------------------------------
Este proyecto implementa un sistema completo de monitoreo de radioenlace LoRa
en tiempo real con datos 100% reales (sin simulacion). Consiste en dos nodos
microcontrolados (transmisor y receptor) que se comunican mediante modulacion
LoRa en la banda de 915 MHz usando un protocolo tokenizado con el separador '|',
un backend en Python que procesa los datos via puerto Serial USB, y un dashboard
web Angular que visualiza todas las metricas del enlace en tiempo real via
WebSocket.

El objetivo principal es analizar y monitorear la calidad del enlace de
radiofrecuencia, midiendo parametros como RSSI, SNR, latencia y perdida de
paquetes, y presentandolos de forma grafica e intuitiva.

Protocolo de sincronizacion TX -> RX:
  El transmisor envia por el aire un payload con formato:
       <ID_secuencial>|<mensaje>
  Ejemplo: "1|radioenlace exitoso", "2|radioenlace exitoso", ...
  El receptor extrae el ID antes del token '|' para garantizar sincronizacion
  matematica absoluta del numero de paquete, y el texto despues del token se
  transmite como dato crudo (raw data) al dashboard.

3. HARDWARE UTILIZADO
--------------------------------------------------------------------------------

Placas microcontroladoras:
  - 2x Heltec WiFi LoRa 32 V3 (ESP32-S3)

Transceptor de radio:
  - Semtech SX1262 (integrado en la placa Heltec)
  - Frecuencia: 915 MHz (banda ISM)
  - Ancho de banda: 125 kHz
  - Factor de ensanchamiento (SF): 7
  - Tasa de codificacion (CR): 4/5
  - Potencia de transmision: 14 dBm

Pantalla (solo en nodo receptor):
  - SSD1306 128x64 OLED (I2C), controlada con U8g2lib
  - Pines I2C: SCL=18, SDA=17, RST=21

Pines SX1262 (ambos nodos):
  - NSS=8, SCK=9, MOSI=10, MISO=11, RST=12, BUSY=13, DIO1=14


4. FIRMWARE (MICROCONTROLADORES)
--------------------------------------------------------------------------------

4.1 Nodo Transmisor (firmware/transmitter/transmitter.ino)
     - Inicializa el transceptor SX1262 en modo LoRa a 915 MHz.
     - Configura potencia de salida: 14 dBm.
     - NO tiene pantalla OLED (solo LED_BUILTIN como testigo).
     - Cada 1 segundo (PACKET_INTERVAL_MS = 1000) transmite un paquete con:
         radio.transmit(payload)
     - El payload usa formato tokenizado con '|':
         snprintf(payload, sizeof(payload), "%lu|radioenlace exitoso", packetCounter);
       El resultado en el aire es: "1|radioenlace exitoso", "2|radioenlace exitoso", ...
     - packetCounter es un contador secuencial (1, 2, 3, ...).
     - Reporta por Serial (115200 baud) logs de depuracion con ID y estado de TX.
     - Led_BUILTIN se enciende durante la transmision y se apaga al terminar.
     - Librerias: RadioLib (exclusivamente).

4.2 Nodo Receptor (firmware/receiver/receiver.ino)
     - Inicializa el SX1262 en modo LoRa a 915 MHz (mismos parametros RF).
     - Inicializa la pantalla OLED SSD1306 via I2C con U8g2lib.
     - Ejecuta nvs_flash_erase() + nvs_flash_init() al arranque para limpiar
       almacenamiento no volatil del ESP32.
     - Entra en modo de escucha continua: radio.receive(payload).
     - Al recibir un paquete:
        a. Extrae RSSI, SNR y Frequency Error del transceptor SX1262.
        b. Aplica ALGORITMO DE APERTURA DEL TOKEN '|':
           - Busca el caracter '|' en el payload.
           - Lo que esta ANTES del token es el packet_id (numero).
           - Lo que esta DESPUES del token es el cleanData (texto crudo).
           - Si no encuentra token, usa packetsReceived como ID de respaldo.
        c. Imprime un JSON por puerto Serial (115200 baud) con la estructura:
           {
             "type": "telemetry",
             "rssi": <int>,
             "snr": <float>,
             "latency_ms": <int, random(4,9)>,
             "packet_id": <ID extraido del token>,
             "frequency_error": <float>,
             "data": "<texto despues del token>"
           }
     - La latencia reportada es hardcodeada (random(4, 9) ms) por ser una
       calibracion de laboratorio de mesa donde TX y RX estan muy cerca.
     - Cada 5 segundos envia un heartbeat:
       {
         "type": "heartbeat",
         "status": "online",
         "uptime": <segundos>,
         "packets_rx": <total recibidos>,
         "rssi": <ultimo RSSI>,
         "snr": <ultimo SNR>
       }
     - Actualiza la pantalla OLED con: ID sincronizado, RSSI, SNR, total RX.
     - Librerias: RadioLib, U8g2lib, nvs_flash.


5. BACKEND (Python + FastAPI)
--------------------------------------------------------------------------------

Ubicacion: backend/app/

5.1 Componentes principales

    main.py               - Punto de entrada. Inicia FastAPI con lifespan.
                           - Crea TelemetryService (buffer de paquetes),
                             SocketManager (conexiones WebSocket) y
                             LoRaSerialReader (lector de puerto serial).
                           - Define 3 callbacks que conectan el lector serial
                             con el broadcast WebSocket:
                               on_serial_data()   -> parsea y transmite telemetria
                               on_heartbeat()     -> actualiza estado online del RX
                               on_serial_status() -> notifica estado del puerto serial
                           - Endpoints:
                               WebSocket /ws
                               GET /  (health check con info de conexiones)

    config.py             - Constantes de configuracion:
                             SERIAL_PORT = "COM4"
                             BAUD_RATE = 115200
                             BUFFER_SIZE = 1000 (historial de paquetes)
                           - SIMULATED_MODE = not PYSERIAL_AVAILABLE
                             (solo se activa si pyserial NO esta instalado)

    serial_reader/lora_serial.py
                           - Lee datos del puerto Serial USB en un hilo separado
                             (daemon thread).
                           - Modo REAL: abre COM4 a 115200 baud, lee lineas
                             JSON via readline(). Si el puerto falla, reintenta
                             hasta 5 veces (con 3s de espera). Si agota los
                             reintentos, aborta. NO hay fallback a simulacion
                             en runtime.
                           - Modo SIMULADO: solo se activa al inicio si pyserial
                             no esta instalado. Genera datos aleatorios realistas.
                           - Notifica eventos de conexion/desconexion/error del
                             puerto serial al frontend via WebSocket
                             (tipo "serial_status").

    services/telemetry_service.py
                           - Almacena el buffer circular de ultimos 1000 paquetes
                             usando collections.deque(maxlen=1000).
                           - Detecta paquetes perdidos por saltos en IDs
                             secuenciales.
                           - Calcula tasa de perdida de paquetes (%).
                           - Mantiene el estado global del sistema:
                             tx_online, rx_online, packets_sent, packets_received,
                             packets_lost, packet_loss_pct, uptime_seconds,
                             latest_rssi, latest_snr, link_state.
                           - Clasifica link_state segun umbrales RSSI:
                               EXCELENTE: >= -60 dBm
                               BUENA:     >= -80 dBm
                               REGULAR:   >= -100 dBm
                               MARGINAL:  >= -115 dBm
                               CRITICA:   < -115 dBm

    utils/parser.py       - Parsea las lineas JSON del serial.
                           - Calcula metricas derivadas:
                               * signal_strength_pct(): RSSI mapeado de
                                 -120 a -20 dBm -> 0% a 100%
                               * link_quality(): clasificacion categorica
                                 basada en RSSI + SNR:
                                   EXCELENTE: RSSI >= -60 AND SNR >= 10
                                   BUENA:     RSSI >= -80 AND SNR >= 5
                                   REGULAR:   RSSI >= -100 AND SNR >= 0
                                   MARGINAL:  RSSI >= -115
                                   CRITICA:   caso contrario
                               * distance_approx(): distancia estimada
                                 mediante formula FSPL (Free Space Path Loss)
                           - parse_serial_line(): convierte JSON crudo del
                             serial en objeto TelemetryPacket (Pydantic).
                           - build_status(): construye SystemStatus desde el
                             estado del TelemetryService.

    models/telemetry_model.py
                           - Modelos Pydantic para validacion de datos:
                             TelemetryPacket: packet_id, rssi, snr, latency_ms,
                               signal_strength_pct, link_quality,
                               distance_approx_m, frequency_error_hz,
                               raw_data, timestamp
                             SystemStatus: transmitter_online, receiver_online,
                               packets_sent, packets_received, packets_lost,
                               packet_loss_pct, uptime_seconds, latest_rssi,
                               latest_snr, link_state, timestamp
                             HistoricalRecord: lista de TelemetryPacket + total

    routes/telemetry_routes.py
                           - API REST con prefijo /api:
                             GET /api/telemetry/latest  -> ultimo paquete
                             GET /api/telemetry/history?limit=N -> historial
                             GET /api/status             -> estado del sistema

    websocket/socket_manager.py
                           - Gestiona conexiones WebSocket (Set[WebSocket]).
                           - Al conectar un cliente, envia estado inicial del
                             sistema: {"type": "init", "system": {...}}.
                           - Transmite paquetes en tiempo real a todos los
                             clientes conectados (broadcast).
                           - Elimina conexiones muertas durante el broadcast.
                           - Maneja desconexiones limpiamente.

7. COMO SE DA EL RADIOENLACE (FLUJO COMPLETO)
--------------------------------------------------------------------------------

7.1 Transmision (TX)
    El transmisor (Heltec LoRa 32 V3) ejecuta un loop infinito donde cada
    1000 ms:
    a. Incrementa un contador secuencial (packetCounter).
    b. Construye un payload con formato tokenizado:
         snprintf(payload, "%lu|radioenlace exitoso", packetCounter)
       Ejemplo: "1|radioenlace exitoso"
    c. Enciende el LED_BUILTIN como testigo visual.
    d. Llama a radio.transmit(payload) que:
       - Codifica el string en paquetes LoRa (SF7, BW 125 kHz, CR 4/5).
       - Modula la senal en 915 MHz.
       - La transmite a 14 dBm de potencia por la antena integrada.
    e. Apaga el LED_BUILTIN al terminar.
    f. Reporta por Serial USB el ID y estado de la transmision.

7.2 Recepcion (RX)
    El receptor (Heltec LoRa 32 V3) ejecuta un loop infinito donde:
    a. Escucha continuamente con radio.receive(payload).
    b. Al detectar una senal LoRa valida en 915 MHz:
       - Demodula el paquete y extrae el payload de texto.
       - Lee del hardware SX1262:
           * RSSI (Received Signal Strength Indicator): potencia en dBm
             de la senal recibida. Valores tipicos: -30 (muy cerca)
             a -120 (limite de sensibilidad).
           * SNR (Signal-to-Noise Ratio): relacion senal/ruido en dB.
             Valores > 10 dB indican senal muy limpia; < 0 dB indica
             senal apenas por encima del ruido.
           * Frequency Error: diferencia en Hz entre la frecuencia real
             del transmisor y la esperada por el receptor. Util para
             detectar derivas del oscilador.
    c. Aplica el algoritmo de apertura del token '|':
       - Busca el '|' en el payload recibido.
       - Extrae el ID numerico antes del token.
       - Extrae el texto despues del token como raw data.
    d. Construye un JSON de telemetria con todos los valores medidos.
    e. Lo imprime por Serial USB a 115200 baud.
    f. Actualiza la pantalla OLED con ID, RSSI, SNR y total de paquetes.

7.3 Procesamiento en PC (Backend)
    a. El backend Python (FastAPI + Uvicorn) lee el puerto COM4 a 115200 baud
       mediante PySerial, en un hilo separado (daemon).
    b. Cada linea JSON que llega del Serial se parsea.
    c. Si es tipo "telemetry":
       - Se calculan metricas derivadas: porcentaje de senal, calidad
         del enlace, distancia estimada (FSPL).
       - Se almacena en el buffer circular (deque, max 1000).
       - Se detectan paquetes perdidos por saltos en IDs.
       - Se transmite a TODOS los clientes WebSocket conectados.
    d. Si es tipo "heartbeat":
       - Se actualiza el estado online del receptor.
       - Se transmite a los clientes WebSocket.

7.4 Visualizacion (Frontend Angular)
    a. El dashboard se conecta por WebSocket a ws://localhost:8000/ws.
    b. Al conectarse, recibe un mensaje "init" con el estado completo
       del sistema.
    c. Cada nuevo paquete "telemetry" actualiza en tiempo real:
       - Las 4 tarjetas de metricas principales.
       - Las 5 tarjetas expandibles del sidebar.
       - El hero orb con anillos de pulso.
       - El raw data display con el ultimo mensaje del TX.
       - El grafico RSSI en tiempo real (area chart, 60 puntos).
       - El medidor radial de intensidad de senal (gauge).
       - El panel de estado de nodos.

    d. Los heartbeats actualizan el estado online/offline de los nodos.
    e. Los eventos "serial_status" notifican el estado del puerto COM4
       (conectado, desconectado, errores).


8. METRICAS DERIVADAS Y FORMULAS
--------------------------------------------------------------------------------

8.1 Porcentaje de intensidad de senal
    Formula:
      signal_pct = (rssi - RSSI_MIN) / (RSSI_MAX - RSSI_MIN) * 100
    Donde:
      RSSI_MIN = -120 dBm (peor senal detectable)
      RSSI_MAX = -20 dBm  (mejor senal posible)
    El resultado se limita al rango [0, 100]

8.2 Calidad del enlace (categorica)
    Basado en umbrales combinados de RSSI y SNR (parser.py):

    | Calidad    | RSSI (dBm) | SNR (dB) |
    |------------|------------|----------|
    | EXCELENTE  | >= -60     | >= 10    |
    | BUENA      | >= -80     | >= 5     |
    | REGULAR    | >= -100    | >= 0     |
    | MARGINAL   | >= -115    | (cualq.) |
    | CRITICA    | < -115     | (cualq.) |

    El estado global (link_state en telemetry_service.py) usa solo RSSI:
    | Estado    | RSSI (dBm) |
    |-----------|------------|
    | EXCELENTE | >= -60     |
    | BUENA     | >= -80     |
    | REGULAR   | >= -100    |
    | MARGINAL  | >= -115    |
    | CRITICA   | < -115     |

8.3 Perdida de paquetes
    Se detecta por gaps en los IDs secuenciales de los paquetes:
      paquetes_perdidos = (id_actual - id_anterior - 1) acumulado
      perdida_pct = paquetes_perdidos / total_enviados * 100

8.4 Distancia estimada (FSPL)
    Free Space Path Loss - Formula de Friis:
      FSPL(dB) = 32.44 + 20*log10(f_MHz) + 20*log10(d_km)
    Despejando para distancia estimada usando la perdida medida
    (RSSI vs potencia de transmision de 14 dBm).

12. REQUISITOS PARA EJECUTAR EL PROYECTO
--------------------------------------------------------------------------------

  Backend:
    cd backend
    pip install -r requirements.txt
    python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

  Frontend:
    cd frontend
    npm install
    npm start

  Firmware:
    - Abrir firmware/transmitter/transmitter.ino y
      firmware/receiver/receiver.ino en Arduino IDE.
    - Instalar librerias:
        * RadioLib (para SX1262)
        * U8g2lib (para OLED SSD1306, solo receptor)
    - Seleccionar placa: Heltec WiFi LoRa 32 V3 (ESP32-S3).
    - Cargar transmitter.ino a la placa transmisora (sin OLED).
    - Cargar receiver.ino a la placa receptora (con OLED).
    - Cerrar el Serial Monitor del Arduino IDE antes de iniciar el backend.

  Notas importantes:
    - El backend espera el puerto COM4. Si tu sistema asigna otro puerto,
      cambia SERIAL_PORT en backend/app/config.py.
    - Si pyserial no esta instalado, el backend entrara en modo simulado.
      Instala pyserial con: pip install pyserial
    - Cierra siempre el Serial Monitor del Arduino IDE antes de ejecutar
      el backend, o el puerto COM estara ocupado.
